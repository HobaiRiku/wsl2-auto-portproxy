# ADR 001：统一生命周期，分别实现 TCP 流与 UDP 报文

状态：首版实现选择；2026-10-08。Windows 原生与 WSL 验收仍是发布门槛。

## 决策

使用 Go 标准库 `net` 维护小型代理内核，不引入 GOST 或独立代理进程。Controller 统一规则、策略、资源身份和状态；TCP 使用双向 `io.Copy` 与 `CloseWrite`，UDP 使用每客户端一个 connected UDP socket。二者共享取消、限额、策略更新、统计和 Stop 契约，不把报文伪装成流。

`inetaf/tcpproxy` 提供了轻量 TCP/半关闭参考，但不提供 UDP。GOST 能统一代理协议，但本项目只需要固定目标的 Windows→WSL 转发。已经在原内核中复现的半关闭和退出问题，适合用明确的 socket 生命周期修复。

## 依据与局限

选型源码审阅版本、链接与具体发现见 [调查计划第 3 节](wslpp-rearchitecture-plan.md)。检查的 GOST `x` HEAD 要求 Go 1.26.3；UDP 默认缓冲、TTL 和请求后关闭语义需要调整，内部 session 包不能直接引用；Pipe 与服务关闭顺序也需要额外行为验证。

此次没有运行 GOST 最小适配 PoC，也没有吞吐/二进制大小比较。此决策基于需求范围、源码适配成本和已经验证的自有内核行为，不能解读为 GOST 性能差或所有版本都不可靠。原计划的两候选同测试比较尚未完成；若未来扩展多协议路由，需要重新评估锁定版本。

## 实现约束

- 每个端点持有自己的策略与运行实例，不保留可变全局代理表或 allowlist。
- TCP 正常 EOF 仅半关闭，异常/Stop/context 取消关闭双方；拨号可取消且有 5 秒超时，空闲长连接不设短 idle timeout。
- UDP session 以客户端地址端口区分，单个 session 使用稳定源端口；支持空报文和异步多回复，64 KiB 读取缓冲、8 报文发送队列、默认 60 秒双向 idle。
- 每个端点默认最多 128 个连接/session，最大配置 1024。没有全局/每 IP 配额，当前只承诺这些已实现的限制。
- Stop 关闭 socket 并等待 worker；未变化的路由不重启。目标/发行版/资源参数变更关闭旧实例再绑定，未实现 listener 保留或 TCP 排空。
- Windows UDP 的 ICMP/截断错误、wildcard 回复源地址及 WSL 真实流量须原生验证。Linux socket 测试与交叉编译不替代这些结果。

## 再评估条件

需要通用代理协议、透明转发、复杂路由或性能测量暴露内核瓶颈时重新选型。先要求候选通过当前行为测试，再比较实际适配代码、维护范围和 Windows 行为；不用功能清单替代协议契约。
